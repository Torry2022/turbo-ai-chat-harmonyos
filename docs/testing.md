# 测试与验收清单

本文覆盖当前 App 的主要功能、跨模块组合和异常恢复流程。自动回归负责状态与存储逻辑，真机验收负责模型执行、系统权限和实际界面。执行结果单独记录，不以清单的存在代替测试通过。

## 1. 如何执行

每轮先记下版本、提交、HAP 的 SHA-256、通用版或实验版、设备和系统版本。只使用新建的测试对话、图片和资料，测试前备份原记录及偏好。确认设备没有其他实验正在运行。

### 主机自动回归

在项目根目录用 PowerShell 执行。Node.js、Python 和 TypeScript 4.9.5 须已安装；`$compilerPath` 指向 TypeScript 的 `lib/typescript.js`，可使用 DevEco 自带版本。

```powershell
$compilerPath = 'D:/Software/DevEco Studio/tools/hvigor/hvigor/node_modules/typescript/lib/typescript.js'
Get-ChildItem scripts/test_*.cjs | ForEach-Object {
  node $_.FullName $compilerPath
  if ($LASTEXITCODE -ne 0) { throw "测试失败：$($_.Name)" }
}
python -m unittest scripts/test_model_catalog.py scripts/test_mnn_catalog_sync.py
if ($LASTEXITCODE -ne 0) { throw '模型目录工具测试失败' }
```

通用版和实验版分别在各自目录执行。GitHub 的 `host-regression.yml` 使用同一组脚本，但不替代 ArkTS 编译和真机测试。

| 自动回归入口 | 主要覆盖范围 |
| --- | --- |
| `scripts/test_chat_history.cjs` | 上下文、记录与附件保存、故障注入、回答版本、编辑、搜索和命名一致性 |
| `scripts/test_conversation_titles.cjs` | 自动命名调度、用户请求抢占、取消与模型释放 |
| `scripts/test_message_selection.cjs` | 跨文本块复制与可见文本拼接 |
| `scripts/test_model_import.cjs`、`test_model_scan_state.cjs`、`test_model_naming.cjs` | 导入预检、扫描状态、命名与目录识别 |
| `scripts/test_catalog_storage.cjs`、两个 Python 测试 | 模型目录缓存、版本要求和目录发布工具 |
| `scripts/test_api_decisions.cjs`、`test_api_server_state.cjs`、`test_laya_runtime.cjs` | API 状态、输入校验、决策模型生命周期与互斥 |
| `scripts/test_reranker.cjs` | 重排输入、排序、取消、释放和服务重启 |
| `scripts/test_runtime_stats.cjs` | 运行状态接口、鉴权与连接异常 |
| 实验版额外的 `test_experimental_api.cjs`、`test_knowledge_relations.cjs` | 客户端上下文隔离、知识关系与实验状态约束 |

`scripts/test_mnn_executor_threads.cpp` 和 `scripts/test_mnn_sampler.cpp` 是 Native 回归程序，需要对应的固定 MNN 源码及编译环境。未编译运行时应记为“未执行”，不能计入上述 CI 的通过结果。

### 构建与安装

```powershell
devecocli build --modules entry --product default --build-mode release
hdc -t <设备地址> install -r <已签名HAP的绝对路径>
```

检查 HAP 内的版本名、版本代码和签名适用设备。覆盖安装后先核对记录是否保留，再开始测试。设备安装和启动须在用户授权范围内进行。

## 2. 真机功能验收

下表的“预期结果”是验收条件。每个用例应记录通过、失败、未执行或阻塞，并附截图、日志或数据指纹。

### 模型与启动

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| M01 | 冷启动、返回前台、强制退出后重开 | 页面正常恢复，原对话保留，无意外跳页或重复消息 |
| M02 | 开关启动自动加载，切换所选模型后重开 | 加载的是设置中指定的模型；关闭时不自动加载 |
| M03 | 从模型页下载、停止、继续并加载 | 文件完整后才允许加载；失败和重试状态明确 |
| M04 | 文件夹、ZIP、推送目录三种方式导入 | 正确识别模型；缺配置、缺权重、无效 ZIP 不注册成可用模型 |
| M05 | 聊天、决策、重排分别加载、释放、切换分类 | 切换分类不影响已加载模型；实际模型和状态一致 |
| M06 | 按 4→6→8→4 线程加载与重载 | 请求值和实际 CPU 宽度一致，推理完成；修改待重载时提示准确 |
| M07 | 文本模型与多模态模型依次加载 | 多模态处理遵守线程设置，释放后可再次加载 |
| M08 | 加载失败后换模型或修正配置重试 | 错误原因可查，失败不留下永久忙碌状态 |
| M09 | 多模态模型识别已知测试图片中的物品、颜色和文字 | 问题不混入测试标记；核对实际答案，不能仅凭生成完成或视觉计时增加判定通过 |

## 3. 执行记录和发布判定

每轮记录以下信息即可，避免只汇报“测试通过”：

| 用例 | 设备与系统 | 版本与提交 | 结果 | 证据或问题 |
| --- | --- | --- | --- | --- |
| C11 | 设备型号 / 系统版本 | 版本号 / 提交号 | 通过、失败、未执行或阻塞 | 截图、日志、文件指纹或复现步骤 |

发现问题后，先保留可重复的失败用例，修正后复测该用例及受影响模块。涉及模型初始化的改动须包含不同加载顺序；涉及保存的改动须包含失败和重启恢复。发布前明确列出仍未执行或受阻的项目。

测试结束后删除自建对话和图片，恢复原会话、主题、模型选择及 API 设置，核对原有记录指纹。下载或导入的模型是否保留，按用户当轮要求处理。

真实存储耗尽和整机断电须另行安排隔离环境。日常验收用可控的文件故障注入和强制结束进程验证恢复，不能将其记成已完成整机断电测试。
