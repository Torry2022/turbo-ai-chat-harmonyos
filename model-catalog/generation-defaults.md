# 模型生成参数的来源与更新

## 发布器规则

生成参数不是逐模型调优的结果，也不必然等于原作者的推荐参数。

发布器按字段依次读取：同一固定提交的 `config.json` → 同仓库的 `generation_config.json`（文件存在时）→ App 兜底值。不会跨仓库猜测原始模型，也不会读取可变的上游分支替代目录固定提交。

| App 字段 | 仓库字段（从左到右优先） | 兜底值 |
| --- | --- | --- |
| temperature | temperature | 0.6 |
| topP | top_p、topP | 0.9 |
| topK | top_k、topK | 40 |
| repetitionPenalty | repetition_penalty、penalty | 1.05 |
| frequencyPenalty | frequency_penalty | 0 |
| presencePenalty | presence_penalty | 0 |
| penaltyWindow | penalty_window | 256 |

同一配置内 snake_case 优先级与当前 MNN 一致。空值继续查找，非数值和非有限数值报错，不悄悄替换。`generation_config.json` 显式要求 `do_sample: false` 时停止自动生成，交由维护者确认；App 当前使用混合采样，不能声称完整复现该解码策略。

这里只映射 App 已支持的字段，不完整复制 sampler 链、min_p、beam search 等设置。最大输出长度不自动采用仓库中的大数值；目录未指定 `maxNewTokens` 时，App 默认 512 tokens。上下文条数与输出 token 上限是不同设置。

## 刷新后何时生效

- **App 内置的 9 个模型**：`ModelManager.profiles()` 优先保留 `MODEL_PROFILES`；在线条目的同 ID profile 不会覆盖它。调整这些预设需要修改 App，而非只发布目录。
- **新增市场模型、尚未安装**：使用当前市场目录配置，安装时保存条目快照。
- **已保存安装快照的市场模型**：安装快照优先于新市场目录。刷新不会强行覆盖与本地模型文件配套的运行配置。
- **当前参数面板**：切换模型或重置生成参数时读取模型默认值；刷新目录不主动重置面板，避免覆盖手动调整。

因此，在线目录更新不代表所有已安装模型立即采用新参数。不应要求用户为更新几个参数重新下载权重；需要迁移时，应另行设计与模型文件版本匹配、保留手动设置的更新流程。

## 历史依据复核与处理结论

以下官方资料核对于 2026-09-18。模型卡与 MNN 转换仓库配置可能不同，不能把后者一概当作原作者推荐值。

### 保留的市场模型参数

- **Qwen3-VL-8B-Instruct**：本地《模型广场真机验证-2026-09-06》的同名小节明确记录，发布参数沿用完成文本、图片、停止与重载测试的 `0.6 / 0.9 / 40 / 1.05`，没有采用发布器推断值。这是有意选择，不是字段遗漏。[原作者模型卡](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct#generation-hyperparameters)还分别给出视觉和纯文本两组参数，视觉组的重复惩罚为 1.0、存在惩罚为 1.5，也不等于 MNN 仓库的重复惩罚 1.2。暂不替换实测配置，更不自动按请求类型切换采样。
- **MiniCPM4-8B**：本地《模型广场真机复测-2026-09-08》明确要求保留实测的导入默认参数、提示词和单轮上下文。原作者[使用示例](https://huggingface.co/openbmb/MiniCPM4-8B#usage)采用温度 0.7、Top-P 0.7，并在 vLLM 示例中使用重复惩罚 1.02；可作为后续对照组，但不能据此宣称当前配置错误或更差。
- **MiniCPM5-2B**：本地《MNN开发快照升级验证》的“MiniCPM5-2B 候选配置”记录了温度 1.0、Top-P 0.95、Top-K 40、重复惩罚 1.0、惩罚窗口 256 的专项测试，包括长输入、多轮召回、输出上限和断连恢复。[原作者建议](https://huggingface.co/openbmb/MiniCPM5-2B#quickstart)也采用温度 1.0、Top-P 0.95。保留现有值，不改回转换仓库的 0.8 / 0.9。Top-K 与惩罚窗口不能因此标成官方推荐；它们属于 App 已验证配置。

这些记录证明的是设置来源和运行验证，不是不同参数之间的效果排名。发布器重新添加同 ID 条目仍会重建运行配置；维护这些条目时，必须先比较差异并保留上述人工选择，不能把自动生成结果直接发布。

### 需要对照验证的内置预设

- **Qwen3-0.6B / 1.7B / 8B**：App 的温度 0.7、Top-P 0.8 与[Qwen3 官方非思考模式建议](https://huggingface.co/Qwen/Qwen3-0.6B#best-practices)一致；官方思考模式建议是 0.6 / 0.95，Top-K 都为 20。代码没有显式传入 `enable_thinking=False`，所以不能把当前参数解释成“App 已关闭思考”。应检查设备实际安装的模板和原始输出，确认默认模式后再做对照；在线 master 配置不能代替设备文件证据。
- **MiniCPM5-1B**：当前 App 的 0.6 / 0.9 与[原作者两种模式建议](https://huggingface.co/openbmb/MiniCPM5-1B#quickstart)均不一致：思考模式为 0.9 / 0.95，非思考模式为 0.7 / 0.95。不能只改为转换仓库的 0.8 / 0.9 就算对齐官方。仍需先核实实际模式；不在此次发布器修复中修改预设或提示词。

对照测试范围限定为这些预设，不必重测全部模型：固定设备文件、提示词和输出预算，只比较温度与 Top-P；使用短问答、简单计算、翻译和连续新对话，记录原生实参、正常结束/截断、重复输出、答案和 token 数。不要以一次回答判断优劣，也不要同时调整模板、重复惩罚或输出上限。已完成的两款模型对照见下节，其余型号尚未测试。

## 2026-09-18 平板参数对照

后续在 USB 连接的 MatePad Edge（QXS-W20）上使用已安装的 v1.10.1 / 1100100 完成 20 次独立 API 请求，没有重新安装 App 或修改模型文件。通过 USB 端口转发访问本机 API，测试结束关闭服务、停止 App 释放模型并移除转发。未记录 API 密钥。

设备上使用内置 MiniCPM5-1B 和已导入的 Qwen3-0.6B。后者不是 App 内置条目：仅借助相同系列的设备模型，对比内置预设中的温度/Top-P 与候选值，不能声称完整复现内置模型的提示词和分发版本。设备实际模板均含 `enable_thinking` 分支，响应均出现思考内容；本轮没有传入关闭思考的模板选项。

所有请求使用同一测试系统提示词“你是一个中文助手，请简洁准确地回答。”，输出上限 512，重复惩罚 1.05，频率/存在惩罚 0，惩罚窗口 256。MiniCPM 的 Top-K 固定为 40；Qwen 的 Top-K 通过面板设为 20，并在原生输出日志中核实。每款模型均先对算术、翻译、短问答各测两组，再将算术重复两次并反转组顺序。未固定随机种子，样本仅用于发现风险，不作统计效果排名。

| 模型 | 温度 / Top-P | 17×23 的三次结果 | 翻译与短问答 |
| --- | --- | --- | --- |
| MiniCPM5-1B 当前值 | 0.6 / 0.9 | 一次达到 512 tokens、仅思考；两次正确回答 391 | 均正常结束 |
| MiniCPM5-1B 思考候选 | 0.9 / 0.95 | 两次正确回答 391；一次达到 512 tokens、仅思考 | 均正常结束 |
| Qwen3-0.6B 内置参数对照 | 0.7 / 0.8 | 357、421、391 | 均正常结束 |
| Qwen3-0.6B 思考候选 | 0.6 / 0.95 | 241、421、一次正常 stop 但仅思考、无正文 | 均正常结束，短问答含明显不当表述 |

MiniCPM 候选组首轮算术成功而当前组截断，但重复后两组均为两次正确、一次截断，不能只挑首轮结果宣称候选更好。Qwen 两组均有算术错误，候选组未表现出改善；错误答案不等同于采样实现故障。本轮也未验证提高输出预算能否解决仅思考无正文，不据此扩大默认上限。

**处理：保留现有预设。** 字段兼容修复可以独立提交；没有证据支持随之批量替换模型参数。未测试的 Qwen3-1.7B / 8B 不从 0.6B 结果外推。设备上的 MiniCPM5-1B INT8 也未混入此次内置模型对照。
